## Primitive 与 UI

Card 由 Header、Content 和 Footer 等区域组成；Primitive 与 UI 使用同一套区域变量。

- **Primitive**：提供 `Card`、`CardHeader`、`CardTitle`、`CardDescription`、`CardExtra`、`CardContent` 和 `CardFooter`。
- **UI**：沿用各框架的内容表达：React、Solid 与 Svelte 使用组件参数；Vue 使用具名 Slots；Angular 使用 inputs、模板与内容投影。

## 何时使用

Card 用于把同一个对象、任务或主题下的信息与操作组织成一个可扫描区域。它适合登录面板、项目概览、统计摘要、设置分组和带操作的内容块。

- 内容本身必须能够形成独立语义；不要为了画边框把页面上的每一段文字都套进 Card。
- 同一页面中的 Card 应保持稳定的信息层级，主要操作不要同时出现在 Header 和 Footer。
- 只有正文内容时可以省略 Header 与 Footer；需要标题、说明或补充状态时再加入对应区域。
- 列表密集、行列关系明确的数据优先使用 List 或 Table，而不是堆叠大量 Card。

## Composition

```text
Card
├── CardHeader
│   ├── CardTitle
│   ├── CardDescription
│   └── CardExtra
├── CardContent
└── CardFooter
```

`CardTitle` 用于标题，`CardDescription` 用于辅助说明，`CardExtra` 用于 Header 的补充内容。

## Header、Extra 与 Footer

`CardExtra` 位于 Header 的补充区域，可放置状态、Badge、时间、菜单或操作。

完整替换 Header 后，不再渲染默认标题、说明与补充区域。

`CardFooter` 用于放置操作、摘要或辅助信息。

## CSS Variables

CSS Variables 可写在单个 Card 上，仅覆盖该实例；也可写在业务容器上统一覆盖容器内的 Card；需要修改全站默认外观时，再放到主题根节点。区域变量优先于 `--card-background`，因此既能只改一个区域，也能一次替换整张 Card。
